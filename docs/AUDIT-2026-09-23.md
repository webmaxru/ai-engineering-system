## Customization seams

Only target-specific settings are customizable. Schema semantics, trust
checks, evidence requirements and approval boundaries are not convenience
switches.

| Surface | Mark/customize | Do not silently change |
| --- | --- | --- |
| Framework verifiers | Adjacent `CUSTOMIZE` comments identify checkout location | Locked identity/hash or blocked conformance |
| Documentation generator/config | Adjacent `CUSTOMIZE` comments identify authored/generated roots, Pages origin/base, branding/repository link | Source-authority boundary or collision checks |
| Northstar governance policy | Paths, commands, owners, checks, retention, risk patterns, App/environment IDs | Fail-closed behavior, approval identity, guide alternatives |
| Hooks/agents/prompts | Runtime invocation, host payload adaptation, context paths and selected tool names | Role capability boundaries and task/plan binding |
| Workflows/scanners | Supported pinned versions, model/budget, runner, triggers, database port, artifact retention | Least privilege, safe-output limits, scanner failure or independent acceptance |
| Application demo | Fictional SKU/key, local port/database endpoint, selected acceptance criteria | Durable idempotency invariant or privacy claims |

Northstar adjacent comments remain **pending** the approved repair. JSON
cannot contain JavaScript comments: use schema-supported `$comment` only
where accepted, otherwise an adjacent documented field map. Do not hand-edit
the snapshot to add comments absent from its exact reference source.

## Repair and acceptance boundary

Created [webmaxru/northstar-orders-api-demo#14](https://github.com/webmaxru/northstar-orders-api-demo/issues/14),
`AES-SURFACE-EVIDENCE`, with scope, constraints, eleven proving criteria and
explicit approval stop. Runtime/control-plane repairs are high-risk
validation-authority changes. The audit request and unattended continuation
are not an independent approval of a digest-bound plan-only commit.

No Northstar implementation was changed. Required next evidence is a reviewed
machine plan, focused negative tests for these defects, clean full validation,
committed process-boundary coverage, host canaries, protected maintenance,
and real trusted hosted acceptance. Until then both locks remain blocked.
This audit is not an exhaustive security certification.
